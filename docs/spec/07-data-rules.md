# 07. Данные и правила: слои, параметры, формулы, переключатели

> Статус: черновик v0.1 · Опирается на: [01. Бухгалтерия](01-accounting.md), [02. Время](02-time.md), [03. Агенты](03-agents.md),
> [04. Производство](04-production.md), [05. Рынки](05-markets.md), [06. Статбюро](06-statistics.md)
> Основа: слои модов в стратегиях Paradox, формулы в данных как в Democracy 4, безопасные языки выражений
> без циклов (Common Expression Language)

Раздел описывает, **как устроены данные, по которым работает ядро**: что лежит в данных, а что в коде, как слои
перекрывают друг друга, как записан параметр и его реалистичная зона, на каком языке пишутся формулы, какие правила
можно переключать и как ГМ меняет их прямо во время партии.

Здесь закрыты два пункта из списка в README: «реалистичная зона» каждого параметра (п. 4) и переключатели правил,
которые ГМ меняет во время партии (п. 6). Первый такой переключатель — `relationship_lending` из раздела 05, п. 10.1.

Приоритет отмечен как **ядро**, **v1** или **v2**, параметры собраны в п. 13.

## 1. Что лежит в данных, а что в коде (ядро)

| В данных | В коде |
| --- | --- |
| Параметры: любое число модели (склонность к сбережению, износ, ставки налогов на старте) | Бухгалтерия: базовые операции и проверки после тика (раздел 01, пп. 6 и 10) |
| Формулы правил поведения ИИ-агентов и ролей (разделы 03–06) | Протоколы рынков: как сводятся заявки и считается клиринг (раздел 05) |
| Переключатели правил: вариант механизма (п. 6) | Детерминизм, потоки случайных чисел, снимки и откат (раздел 02, пп. 7 и 8) |
| Каталоги: товары, рецепты, отрасли, технологии с датами, законы, события, шоки | Исполнитель формул и проверка данных (пп. 5 и 11) |
| Календарь событий и порядок модулей в тике (раздел 02, пп. 1.1 и 5) | Интерфейсы игроков и ГМ |
| Рычаги политики: кто и в каких пределах их меняет (п. 7) | |

Главное правило: **данные не могут сломать бухгалтерию**. Формула только возвращает решение: сколько потратить,
какую цену поставить, выдать ли кредит. Исполняет решение модуль через базовые операции раздела 01, поэтому даже
бессмысленная формула не создаст деньги из воздуха и не нарушит баланс (раздел 03, п. 1, принцип 6).

## 2. Слои (ядро)

Мир собирается из слоёв. Каждый следующий слой перекрывает предыдущий, как моды в стратегиях Paradox.

```mermaid
flowchart LR
    B["База: физика экономики"] --> E["Пакет эпохи"]
    E --> A["Дополнения: 0 или больше"]
    A --> S["Сценарий: страны из конструктора"]
    S --> G["Правки ГМ во время партии"]
```

| Слой | Что задаёт | Кто пишет |
| --- | --- | --- |
| База | общие формулы по умолчанию, общие для всех эпох товары и отрасли, описания параметров (п. 4) | разработчики |
| Пакет эпохи | каталог товаров и рецептов с годами появления (раздел 04, пп. 1 и 5), институты и законы эпохи, денежный режим, ИИ-правила ролей (раздел 03, п. 7.2), календарь статистики (раздел 06, п. 2), значения параметров по умолчанию для эпохи | разработчики, авторы эпох |
| Дополнения | отдельные механизмы, применимые в любой эпохе: плановая экономика, конкретные нелегальные рынки, детальные 64 отрасли | разработчики, моддеры |
| Сценарий | страны, регионы и стартовое состояние из конструктора партии (раздел 08) | ГМ до партии |
| Правки ГМ | любые изменения во время партии (п. 8) | ГМ |

Дополнения подключаются в заданном порядке. Если два дополнения меняют одно значение, побеждает подключённое позже, а проверка
данных выдаёт предупреждение о конфликте (п. 11).

### 2.1. Как слой меняет данные

| Что меняется | Как перекрывается |
| --- | --- |
| Параметр | значение верхнего слоя заменяет нижнее |
| Запись каталога (товар, рецепт, закон) | по `id`: новый `id` добавляет запись, существующий меняет только указанные поля, `remove: true` убирает запись |
| Формула | заменяется целиком по `id` слота (п. 5.1) |
| Список (порядок модулей, календарь) | операции `insert_before`, `insert_after`, `remove` по `id` элемента, чтобы два слоя не затирали список друг друга |

## 3. Где действует значение (ядро)

Значение параметра можно задать на разных уровнях: мир → страна → регион → отрасль или тип агента → отдельный агент.
Пример: склонность к потреблению по миру 0,8, в стране A 0,75, в бедном регионе этой страны 0,9.

**Правило выбора значения.** Сначала берётся самый узкий уровень, где значение задано. Внутри одного уровня побеждает
верхний слой. Поэтому правка ГМ на уровне мира не затрёт значение, которое сценарий задал для одной страны.
Панель ГМ показывает, где задано действующее значение, и предлагает применить правку ко всем уровням сразу.

Разнородность агентов (раздел 03, п. 1, принцип 4) задаётся распределением `{mean, sd, min, max}`. Каждый агент получает своё значение
при создании. Правка распределения во время партии меняет новых агентов сразу, а действующих — только если ГМ выбрал
«пересчитать всех».

## 4. Параметр и его реалистичная зона (ядро)

Каждый параметр в данных описан одной записью:

```yaml
param: price_review_prob
meaning: "вероятность пересмотра цены за тик при нулевой инфляции"
unit: per_tick
type: number               # number / share / distribution / enum / table_by_year
range: [0, 1]              # допустимые значения: вне них данные не загрузятся
zone: [0.08, 0.30]         # реалистичная зона: вне неё предупреждение
zone_source: "Nakamura, Steinsson 2008; Bils, Klenow 2004"
default: 0.2
scope: [world, country, industry]
edit: live                 # когда можно менять: live / turn / setup (п. 6.1)
```

- **Диапазон** `range` — то, без чего модель теряет смысл: вероятность от 0 до 1, срок не меньше 1 тика. Значение
  вне диапазона отклоняется.
- **Реалистичная зона** `zone` — значения, которые встречаются в реальных экономиках и исследованиях. Выход за зону
  не запрещён, потому что ГМ может хотеть исторический или фантастический сценарий. Но ГМ видит предупреждение, а в разборе
  партии (раздел 06, п. 7) остаётся пометка, какие параметры были вне зоны.
- Зона может зависеть от эпохи: например, норматив капитала банков 8% появился только в 1988 году, поэтому в пакете
  межвоенной эпохи у него другая зона.

Примеры зон:

| Параметр | По умолчанию | Зона | Почему такая |
| --- | --- | --- | --- |
| `price_review_prob` (раздел 03, п. 12.3) | 0,2 | 0,08–0,30 за тик | в США обычные цены меняются у 9–12% товаров в месяц, с распродажами около 20% (Nakamura, Steinsson 2008) |
| `taylor_phi_pi` (раздел 03, п. 12.5) | 1,5 | 1,0–2,5 | ниже 1 ЦБ не удерживает инфляцию (принцип Тейлора); ФРС до 1979 года реагировала слабее, чем после (Clarida, Galí, Gertler 2000), поэтому значение ниже 1 — исторический сценарий 1970-х, а не ошибка |
| `car_min` (раздел 03, п. 12.4) | 0,08 | 0,08–0,15 после 1988 года | Базель I задал минимум 8%, с буферами Базеля III требования выше |
| `delta_equipment` (раздел 04, п. 14.2) | 0,010 | 0,006–0,02 за тик | износ оборудования около 7–21% в год |

Зоны остальных параметров заполняются вместе с калибровкой (разделы 08 и 10). Параметр без зоны допустим, но проверка
данных отмечает его как «зона не задана».

## 5. Язык формул (ядро)

### 5.1. Слоты

Каждое правило поведения из разделов 03–06 — это **слот** с постоянной подписью: какие входы доступны, что формула
возвращает и в каких пределах. Например:

| Слот | Входы | Выход |
| --- | --- | --- |
| `cb.policy_rate` | ожидаемая инфляция, цель, оценка разрыва выпуска, прошлая ставка, параметры правила | ставка, обрезается по `rate_floor` и шагу `rate_step` |
| `firm.markup_step` | запас к продажам, доля рынка, прошлая наценка | изменение наценки, обрезается по `L_min`–`L_max` |
| `hh.consumption` | ожидаемый доход, деньги на счетах, целевой запас, жильё, ожидаемая инфляция (раздел 03, п. 3.3) | расходы на потребление, не больше доступных денег и кредита |

Пакет эпохи, сценарий или ГМ заменяют формулу в слоте. Если формула вернула значение вне пределов слота, оно обрезается,
а в журнал пишется предупреждение.

### 5.2. Что умеет язык

Язык похож на формулы в электронной таблице:

- числа, логические значения, варианты из списка (`fixed`, `float`);
- арифметика, сравнения, `and`, `or`, `not`, `if(условие, да, нет)`;
- функции `min`, `max`, `clamp`, `abs`, `exp`, `ln`, `sqrt`, `pow`, `logistic`, `round(x, шаг)`;
- прошлое: `lag(x, n)` — значение `n` тиков назад, `avg(x, n)` — среднее за `n` тиков;
- случайность: `rand_normal(среднее, sd)` и `rand_uniform(a, b)` берут числа из потока своего модуля (раздел 02, п. 7);
- вспомогательные формулы с именем (`let`), без рекурсии.

Чего в языке нет: циклов, рекурсии, доступа к файлам и сети, изменения балансов. Поэтому любая формула заканчивается
за предсказуемое время, как в Common Expression Language, который тоже сделан без полноты по Тьюрингу ради скорости и
безопасности. Сумма или среднее по агентам доступны только через готовые показатели (`cpi_yoy_official`, `sales_share`),
а не перебором агентов в формуле.

Правило Тейлора из раздела 03, п. 7.2 в данных выглядит так:

```yaml
slot: cb.policy_rate
formula: |
  let i_star = r_star + exp_infl_12 + phi_pi * (exp_infl_12 - pi_target) + phi_y * gap_est
  max(rate_floor, round(rho * lag(policy_rate, 1) + (1 - rho) * i_star, rate_step))
```

### 5.3. Формула видит только то, что видит её владелец

Каждая формула принадлежит роли или типу агента и может читать только их информацию (раздел 02, п. 6; раздел 06, п. 7).
Постоянное распоряжение игрока-ЦБ может использовать `cpi_yoy_official`, но не истинную инфляцию `cpi_yoy_true`.
Проверка отклоняет такую формулу при загрузке. Истинные счета доступны только формулам ГМ (события и сценарии кризисов).
Без этой проверки через формулу можно было бы подсмотреть истинную экономику.

### 5.4. Скорость и детерминизм

- Формула разбирается и проверяется один раз, при загрузке или правке, и дальше исполняется как готовая программа,
  а не разбирается заново каждый тик. Это нужно, чтобы уложиться в цели по скорости (раздел 02, п. 9): формулы агентов
  считаются десятки тысяч раз за тик.
- Размер формулы ограничен `formula_max_nodes` узлами.
- Порядок вычислений и арифметика с плавающей точкой те же на всех машинах (раздел 02, п. 7).
- **Единицы измерения (v1).** Проверка предупреждает, если формула складывает величины в разных единицах: деньги
  и доли, годовые и месячные ставки.

## 6. Переключатели правил (ядро)

Переключатель — параметр-список, который выбирает вариант механизма. Например, `relationship_lending: on / off`
(раздел 05, п. 10.1).

### 6.1. Когда можно переключать

У каждого переключателя и параметра есть класс `edit`:

| Класс | Когда меняется | Пример |
| --- | --- | --- |
| `live` | в любой момент партии; действует с начала следующего тика (шаг 0, раздел 02, п. 5) | `relationship_lending`, правило ожиданий у типа агента |
| `turn` | только между ходами | порядок модулей в тике, перевод бюджетных денег из ЦБ в коммерческий банк |
| `setup` | только в конструкторе партии, до разгона (раздел 08) | число доходных классов, детальность отраслей |

Если переключатель меняет устройство мира, у него есть **переходная процедура**, и она тоже работает через базовые
операции, чтобы бухгалтерия сходилась. Пример: при переводе счёта казначейства в коммерческий банк остаток переносится
операцией `transfer` на шаге 0.

### 6.2. Переключатели из разделов 01–06

| Переключатель | Где описан | Варианты | Класс |
| --- | --- | --- | --- |
| `relationship_lending` | 05, п. 10.1 | `on` (по умолчанию) / `off` | `live` |
| Правило ожиданий по типу агента | 03, п. 2.2 | `adaptive` / `econometric` / `naive` / `trend` | `live` |
| Нелегальные рынки в ВВП | 06, п. 3.1 | нет (по умолчанию) / да | `live`, действует с ближайшего базового пересмотра |
| `provisioning_rule` (резервы банков на потери) | 03, п. 12.4 | `expected_loss` / `overdue` | `turn` |
| Где хранятся деньги бюджета | 01, п. 2.1 | счёт в ЦБ / в коммерческом банке | `turn`, с переходной процедурой |
| Где банковский надзор | 03, п. 8.6 | в ЦБ / отдельно | `turn` |
| Число доходных классов | 03, п. 13 | 10 / 5 | `setup` |
| Детальность отраслей | 04, п. 2 | 35 / 64 | `setup` |
| Плановая экономика | 03, п. 8.8 | рыночная / плановая | `setup` в v1; переход во время партии как реформа — v2 |

Новые переключатели добавляются в данных вместе с вариантами механизма, без правки ядра.

## 7. Рычаги политики (ядро)

Рычаги — то, что игроки меняют приказами: ставки налогов, ставка ЦБ, расходы, потолки цен, режим курса. Это не правила,
а состояние мира. Стартовое значение задаёт сценарий, дальше его меняют приказы (раздел 02, п. 3).

Данные описывают каждый рычаг:

```yaml
lever: vat_rate
role: finance_ministry        # кто может менять
range: [0, 0.4]
zone: [0.05, 0.27]
effective: next_tax_period    # когда вступает в силу: next_tick / next_tax_period / budget_year
requires: []                  # условия: закон эпохи, согласие другой роли
```

Набор рычагов по ролям описан в разделе 03, пп. 7–8. Право роли менять рычаг тоже лежит в данных: например, Минфин
не может менять ставку ЦБ, если ЦБ независим (раздел 02, п. 3).

## 8. Правки ГМ во время партии (ядро)

- ГМ может изменить любое значение, формулу, переключатель или запись каталога, если это разрешает класс `edit` (п. 6.1).
- Каждая правка — запись в журнале партии: тик, кто, что (слой, уровень, `id`), старое и новое значение, причина,
  видна ли игрокам.
- Правка вступает в силу с шага 0 следующего тика. Поэтому повтор партии из снимка с тем же журналом даёт тот же результат
  до копейки (раздел 02, пп. 7 и 8).
- Откат к снимку отменяет и правки после него. В ветке мира ГМ может сделать другие правки.
- Временная правка с затуханием — это шок, он описан в разделе 09.
- **Что видят игроки.** Смена переключателя правил объявляется игрокам как «изменение правил игры». Правка параметров
  поведения и шоки по умолчанию скрыты, пока ГМ сам их не откроет. Все правки видны в разборе партии.

## 9. Пакеты эпох и дополнения (ядро — формат, первая эпоха — v1)

Пакет эпохи задаёт каталог товаров и рецептов с годами появления (раздел 04, пп. 1 и 5). Общие для всех эпох записи он
наследует из базы. Чтобы партия могла пережить границу эпохи, каталог включает и записи с годами после её конца: партия,
начатая в 1965 году, к 1975 году сама получит технологии 1970-х. Кроме каталога, пакет эпохи задаёт институты и значения
по умолчанию:

| Что задаёт пакет эпохи | Пример |
| --- | --- |
| Денежный режим и правила ЦБ | золотой стандарт и `gold_cover`, Бреттон-Вудс, плавающий курс (раздел 03, п. 7.2) |
| Законы | о банкротстве, о банках (`car_min`), о труде (`severance_months`), налоговый кодекс (раздел 03, п. 8.2) |
| ИИ-правила ролей | бюджетное правило, правило ЦБ эпохи |
| Статистика | календарь показателей и методика (раздел 06, п. 2) |
| Значения по умолчанию | индексация зарплат, память о высокой инфляции, частота пересмотра цен |

Смена эпохи в ходе партии не происходит сама. Институты меняются только приказами игроков (например, отказ от фиксации
курса) или событием ГМ (например, конец Бреттон-Вудса в 1971 году).

Концепция предлагает 4 эпохи: межвоенная (1920–1939), Бреттон-Вудс (1945–1971), стагфляция и либерализация (1971–1999),
глобализация и цифра (2000–сейчас). Плановая экономика — дополнение для любой эпохи.

## 10. Формат файлов, версии и сохранения (ядро)

- **Формат.** Данные пишутся в YAML, его удобно читать и комментировать. Каждый вид записи проверяется схемой
  (JSON Schema). Идентификаторы английские, названия для интерфейса на нескольких языках: `name: {ru: ..., en: ...}`.
- **Деньги в данных** записываются в основных единицах валюты (рублях) и при загрузке переводятся в минимальные (копейки),
  как требует раздел 01, п. 9. Даты — `ГГГГ-ММ`.
- **Заголовок файла:** `id`, слой, версия, зависимости (`requires`): например, дополнение «плановая экономика» требует
  базу не старше указанной версии.
- **Сохранение партии** содержит полную копию всех слоёв на момент старта, снимки и журнал приказов и правок ГМ.
  Поэтому партию можно повторить, даже если базовые данные потом обновились.
- **Обновление базы во время партии** не применяется само. ГМ видит список отличий и может принять их как свою правку.

## 11. Проверка данных при загрузке (ядро)

Проверка запускается при загрузке слоёв, при каждой правке ГМ и перед стартом партии. Она выдаёт три уровня сообщений:

| Уровень | Что значит | Примеры |
| --- | --- | --- |
| Ошибка | партия не запустится, правка не примется | значение вне `range`; ссылка на несуществующий товар; формула читает данные, которых нет у её владельца (п. 5.3); рецепт без выхода; цикл в зависимостях дополнений |
| Предупреждение | можно продолжать, но ГМ должен знать | значение вне реалистичной зоны; два дополнения меняют одно значение; товар, который никто не производит и не импортирует; на рынке меньше 3 фирм, а данные не объявили монополию (раздел 08) |
| Сведения | для автора данных | параметр без зоны; формула вернула значение вне пределов слота за последний тик |

Проверку стартового баланса (раздел 01, п. 10) и разгона делает генератор (раздел 08).

## 12. Связь с другими разделами

- Правила разделов 03–06 — формулы по умолчанию в слотах (п. 5.1), их параметры — записи п. 4.
- Постоянные распоряжения игроков (раздел 02, п. 3) пишутся на языке формул п. 5 и проходят проверку видимости п. 5.3.
- Шоки и события ГМ (раздел 09) — временные правки данных из п. 8.
- Конструктор и генератор (раздел 08) создают слой сценария и проверяют стартовое состояние.
- Набор тестов (раздел 10) проверяет, что значения по умолчанию лежат в реалистичных зонах, а модель с ними даёт
  реалистичные ряды.

## 14. Какие кризисы позволяет этот раздел

Сам слой данных кризисов не создаёт. Но через переключатели, рычаги и правки ГМ в партию входят институциональные
причины кризисов:

| Кризис | Как его включают |
| --- | --- |
| Конец Бреттон-Вудса, выход из золотого стандарта | приказ игрока или событие ГМ меняет денежный режим; курс и инфляция реагируют сами (раздел 03, пп. 7.2 и 7.4) |
| Волна набегов на банки | правка `insurance_cap` до нуля, то есть отмена страхования вкладов (раздел 03, пп. 3.8 и 5.5) |
| Сжатие кредита после смены правил резервов | `provisioning_rule` переходит на `expected_loss`, банки сразу досоздают резервы и режут кредит |
| Обвал заёмщиков без истории | `relationship_lending: on` при крахе крупного банка: его клиенты не могут быстро занять в другом месте (раздел 05, п. 10.1) |
| Ошибка из-за бессмысленной настройки | не кризис, а артефакт; от него защищают реалистичные зоны и проверка данных (пп. 4 и 11) |

## 15. Открытые вопросы

- [ ] Правило выбора значения (предлагаю: сначала самый узкий уровень, где значение задано, внутри уровня — верхний слой;
  панель ГМ показывает, откуда взято значение).
- [ ] Реалистичная зона (предлагаю: выход за зону не запрещён, но ГМ видит предупреждение, а в разборе партии остаётся пометка).
- [ ] Язык формул (предлагаю: свой маленький язык без циклов и рекурсии по образцу Common Expression Language; формула видит
  только данные своего владельца).
- [ ] Классы правок `live` / `turn` / `setup` и распределение переключателей по ним (предлагаю: как в таблице п. 6.2).
- [ ] Видимость правок ГМ (предлагаю: смена правил объявляется игрокам, правки параметров и шоки скрыты, пока ГМ их не откроет).
- [ ] Порядок эпох (предлагаю: первой сделать 2000–сейчас, потому что для неё больше всего данных для калибровки; потом
  1971–1999, 1945–1971 и 1920–1939; плановая экономика — дополнение в v1).
