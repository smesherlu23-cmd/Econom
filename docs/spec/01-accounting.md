# 01. Бухгалтерия: секторы, инструменты, балансы и потоки

> Статус: согласован (v1.1) · Основа: Godley–Lavoie (stock-flow consistent), СНС-2008, Caiani et al. (AB-SFC benchmark)

Бухгалтерия — фундамент движка. Любое изменение денег, долгов, акций и имущества в модели проходит через
небольшой набор операций с двойной записью. Поэтому деньги не появляются из ниоткуда и не исчезают,
а нарушение баланса означает ошибку в коде, а не «экономический эффект».

Этот раздел задаёт:

1. какие есть секторы и инструменты (что может лежать в балансе агента);
2. матрицу балансов (кто чем владеет и кому должен);
3. матрицу потоков (какие платежи бывают за тик);
4. базовые операции, через которые единственно можно менять балансы;
5. запись сделки и её признаки (задекларирована ли, наличными ли, законна ли);
6. истинную и официальную экономику;
7. проверки (инварианты), которые выполняются после каждого тика.

---

## 1. Секторы

Каждый агент принадлежит одному сектору. Сектор определяет, какие инструменты агент может держать и выпускать.
В мире с несколькими государствами у каждого государства свой полный набор секторов; «остальной мир» —
это все сектора других стран с точки зрения данной страны.

| Код | Сектор | Кто это в модели |
| --- | --- | --- |
| `HH` | Домохозяйства | когорты: регион × возраст × квалификация × доходный дециль; отдельная когорта «чиновники» |
| `NFC` | Нефинансовые фирмы | крупные поимённо, малый бизнес когортами; признак `state_owned` для госкомпаний |
| `BANK` | Коммерческие банки | поимённо, 5–50 на страну |
| `OFI` | Прочие финансовые посредники | инвестфонды, страховщики, пенсионные фонды, МФО, теневой банкинг |
| `CB` | Центральный банк | один на валюту |
| `GOV` | Государство | центр, регионы, внебюджетные фонды |
| `CRIME` | Группировки | организованная преступность; держит наличные и депозиты, владеет фирмами через подставных лиц |
| `ROW` | Остальной мир | для страны — все агенты других стран; ИИ-страны представлены агрегатно |

## 2. Инструменты

### 2.1. Финансовые инструменты

У финансового инструмента всегда есть **эмитент** (для кого он обязательство) и **держатель** (для кого он актив),
а также **валюта**. Поэтому сумма по любому финансовому инструменту в любой валюте по всем агентам мира равна нулю.

| Код | Инструмент | Эмитент (обязательство) | Типичные держатели | Примечание |
| --- | --- | --- | --- | --- |
| `CASH` | Наличные | `CB` | `HH`, `NFC`, `BANK` (касса), `CRIME`, `ROW` | основа тени и паник вкладчиков |
| `RES` | Резервы на корсчетах | `CB` | `BANK` | через них идут расчёты между банками |
| `TSA` | Счёт казначейства | `CB` | `GOV` | деньги бюджета; вариант «счёт в коммерческом банке» — настройка |
| `DEP` | Депозиты (до востребования и срочные) | `BANK` | все небанковские секторы | могут быть в иностранной валюте (долларизация) |
| `LOAN` | Кредиты | заёмщик | `BANK`, `OFI` | ипотека, потребительские, корпоративные, госкредиты |
| `CBL` | Кредиты ЦБ банкам | `BANK` | `CB` | рефинансирование, кредитор последней инстанции |
| `GB` | Государственные облигации | `GOV` | `BANK`, `OFI`, `CB`, `HH`, `ROW` | разные сроки и валюты |
| `CBOND` | Корпоративные облигации | `NFC`, `BANK` | `BANK`, `OFI`, `HH`, `ROW` | |
| `EQ` | Акции и доли | `NFC`, `BANK`, `OFI` | все, кроме `CB` | по рыночной стоимости, как в СНС |
| `FUND` | Паи, страховые и пенсионные резервы | `OFI` | `HH`, `NFC` | |
| `TC` | Торговый кредит и просрочка между фирмами | покупатель | продавец | здесь живут неплатежи |
| `TAXA` | Налоговая задолженность | налогоплательщик | `GOV` | недоимки и штрафы |
| `IFL` | Кредиты международного кредитора | `GOV`, `CB` | `ROW` (аналог МВФ) | с условиями, управляет ГМ |

Золотовалютные резервы — это не отдельный инструмент, а инструменты в чужой валюте (депозиты и облигации других стран),
которыми владеет `CB`, плюс монетарное золото.

### 2.2. Нефинансовые (реальные) активы

У реальных активов нет эмитента: они чьё-то имущество, но ничей долг. Поэтому их сумма по миру не ноль, а их общая стоимость.
По СНС монетарное золото считается финансовым активом без встречного обязательства. В модели оно стоит среди реальных активов,
потому что учитывается так же: у него нет эмитента, а сумма по миру не равна нулю.

| Код | Актив | Кто держит |
| --- | --- | --- |
| `K` | Основной капитал по видам (здания, оборудование, транспорт) | `NFC`, `BANK`, `OFI`, `GOV` |
| `INV` | Запасы товаров (сырьё, полуфабрикаты, готовая продукция) | `NFC`, `GOV` (госрезерв), `HH` (запасы «на всякий случай») |
| `LAND` | Земельные участки | все, кроме `CB` |
| `HOUSE` | Жильё | `HH`, `NFC`, `GOV` |
| `INFRA` | Инфраструктура (дороги, сети, порты) | `GOV`, `NFC` (естественные монополии) |
| `NATRES` | Разведанные запасы природных ресурсов | `GOV`, `NFC` (по лицензии) |
| `GOLD` | Монетарное золото | `CB` |

Все реальные активы учитываются в натуральных единицах и в стоимости. Стоимость пересчитывается по рыночным ценам (переоценка, см. п. 5).

## 3. Матрица балансов

Строки — инструменты, столбцы — секторы. `+` — актив, `−` — обязательство, `±` — сектор бывает и держателем, и эмитентом,
пустая клетка — сектор этот инструмент не держит. Например, межбанковский кредит — `LOAN` банка у банка, а валютные
резервы ЦБ — депозиты в иностранных банках и облигации других стран.
Для каждой страны и валюты строится своя матрица; в мире с несколькими странами действует правило сложения по всем странам.

| Инструмент | HH | NFC | BANK | OFI | CB | GOV | CRIME | ROW | Σ |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| CASH | +Cₕ | +C_f | +C_b | | −C | | +C_c | +C_r | 0 |
| RES | | | +R | | −R | | | | 0 |
| TSA | | | | | −T | +T | | | 0 |
| DEP | +Dₕ | +D_f | ±D_b | +D_o | +D_cb | +D_g | +D_c | ±D_r | 0 |
| LOAN | −Lₕ | −L_f | ±L_b | +L_o | | −L_g | | ±L_r | 0 |
| CBL | | | −A | | +A | | | | 0 |
| GB | +Bₕ | | +B_b | +B_o | +B_cb | −B | | ±B_r | 0 |
| CBOND | +Qₕ | −Q_f | ±Q_b | +Q_o | | | | +Q_r | 0 |
| EQ | +Eₕ | −E_f | ±E_b | ±E_o | | +E_g | +E_c | ±E_r | 0 |
| FUND | +Fₕ | +F_f | | −F | | | | | 0 |

| K, INV, LAND, HOUSE, INFRA, NATRES | + | + | + | + | | + | + | | Σ реальных активов |
| GOLD | | | | | +Au | | | | Au |
| **Чистая стоимость** | NWₕ | NW_f | NW_b | NW_o | NW_cb | NW_g | NW_c | NW_r | Σ реальных активов |

Чистая стоимость сектора — сумма его столбца:

```math
NW_s = \sum_{i \in \text{активы}} A_{i,s} - \sum_{j \in \text{обязательства}} L_{j,s}
```

Так как акции учитываются как обязательство фирмы по рыночной стоимости (СНС), чистая стоимость фирмы
показывает разрыв между балансовой стоимостью её имущества и тем, как её оценивает биржа. Поэтому для банкротства
и нормативов капитала берётся собственный капитал без учёта своих акций: имущество минус долги (раздел 03, пп. 4.9 и 5.1).

`+D_g` появляется, только если деньги бюджета хранятся в коммерческом банке (настройка, п. 2.1).

## 4. Матрица потоков за тик

Строки — потоки за тик, столбцы — секторы. Для фирм и банков текущий счёт отделён от капитального:
на текущем считаются доходы и расходы, на капитальном — инвестиции и их финансирование.
**Каждая строка и каждый столбец в сумме дают ноль.** Нижняя часть матрицы — изменения финансовых
инструментов: так видно, чем профинансирован каждый дефицит. Строка «Чистое кредитование» — промежуточный итог
верхней части столбца, в сумму столбца она не входит.

или снятием с казначейского счёта `ΔT`.

## 5. Связь запасов и потоков

Остаток инструмента на конец тика равен остатку на начало, плюс поток из матрицы потоков, плюс переоценка, плюс прочие изменения объёма:

```math
S_{i,s,t} = S_{i,s,t-1} + F_{i,s,t} + \text{Reval}_{i,s,t} + \text{OV}_{i,s,t}
```

- **Поток** `F` — сделки этого тика (п. 4).
- **Переоценка** `Reval` — изменение цены без сделки: курс акций, цена облигаций, валютный курс, цена земли и жилья, цена запасов.
  У финансового инструмента переоценка проводится одновременно у держателя и у эмитента, поэтому нулевая сумма сохраняется.
- **Прочие изменения объёма** `OV` — события без платежа: списание безнадёжного долга при банкротстве, конфискация,
  разрушение имущества (катастрофа, война), открытие месторождения, амортизация, порча запасов.

Отсюда уравнение чистой стоимости, которое проверяется для каждого агента:

```math
NW_{s,t} = NW_{s,t-1} + S_{s,t} + KT_{s,t} + \text{Reval}_{s,t} + \text{OV}_{s,t}
```

Здесь `S` — сбережение: доходы минус текущие расходы, до вычета износа (износ входит в `OV`). Со строкой матрицы потоков
оно связано так: `NL = S + KT − I − ΔINV`. Инвестиции и прирост запасов меняют состав имущества, но не чистую стоимость.

## 6. Базовые операции

Код меняет балансы **только** через эти операции. Ни одна другая часть движка не имеет права напрямую писать в баланс агента.
Это главное правило для разработки: оно делает ошибки бухгалтерии невозможными по построению.

| Операция | Что делает | Пример |
| --- | --- | --- |
| `transfer(instr, issuer, from, to, amount)` | переводит актив от одного держателя другому, эмитент не меняется | оплата с депозита на депозит в одном банке, передача наличных |
| `issue(instr, issuer, holder, amount)` | создаёт пару «актив держателя — обязательство эмитента» | выдача кредита, размещение облигаций, эмиссия наличных |
| `redeem(instr, issuer, holder, amount)` | гасит такую пару | погашение кредита, выкуп облигаций |
| `revalue(instr, issuer, holder, delta)` | меняет стоимость без сделки у обеих сторон | переоценка акций по биржевой цене |
| `write_off(instr, issuer, holder, amount)` | гасит пару без оплаты | дефолт по кредиту, списание долга |
| `real_change(asset, owner, qty, value)` | меняет реальный актив | выпуск продукции, амортизация, разрушение, открытие месторождения |

Из базовых операций собираются составные. Главная — **платёж**:

- **безналичный, оба в одном банке:** `transfer(DEP, bank, payer, payee)`;
- **безналичный, разные банки:** депозит плательщика гасится `redeem(DEP, bank_payer, payer)`, депозит получателя создаётся `issue(DEP, bank_payee, payee)`, а банк плательщика переводит банку получателя столько же резервов `transfer(RES, cb, bank_payer, bank_payee)`. Если резервов не хватает, банк плательщика сначала занимает их на межбанке или в ЦБ;
- **наличными:** `transfer(CASH, cb, payer, payee)`;
- **в иностранной валюте:** то же самое в инструментах этой валюты; если у плательщика нет валюты, сначала идёт сделка на валютном рынке;
- **бартер:** два `real_change` встречных товаров без финансовых операций; для статистики сделка оценивается по рыночным ценам.

Так межбанк, нехватка ликвидности и паника вкладчиков возникают сами из обычных платежей, без отдельных формул.

### Пример: кредит, зарплата, наличные

Фирма обслуживается в банке A, домохозяйство — в банке B. Показаны только изменения балансов.

| Шаг | Операция | Фирма | Домохозяйство | Банк A | Банк B | ЦБ |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Банк A выдаёт фирме кредит 50 | депозит +50, долг по кредиту +50 | | кредит (актив) +50, депозит (долг) +50 | | |
| 2 | Фирма платит зарплату 30 | депозит −30 | депозит +30 | депозит (долг) −30, резервы −30 | депозит (долг) +30, резервы +30 | |
| 3 | Банку A не хватает резервов, он занимает 10 у ЦБ | | | резервы +10, долг ЦБ +10 | | кредит банку +10, резервы (долг) +10 |
| 4 | Домохозяйство снимает 5 наличными | | депозит −5, наличные +5 | | депозит (долг) −5, резервы −5 | резервы (долг) −5, наличные (долг) +5 |
| 5 | Фирма гасит 20 кредита | депозит −20, долг по кредиту −20 | | кредит −20, депозит (долг) −20 | | |

Что видно из примера:

- шаг 1 создаёт деньги (депозиты в экономике выросли на 50), шаг 5 их уничтожает — так работает кредитная эмиссия в реальных банках;
- шаг 2 не меняет количество денег, но перемещает резервы между банками и создаёт банку A потребность в ликвидности;
- шаг 4 показывает, почему массовое снятие наличных опасно: оно напрямую съедает резервы банка, и без ЦБ банк быстро
  теряет ликвидность и перестаёт проводить платежи, даже если его капитал в порядке.

## 7. Запись сделки

Каждая составная операция порождает запись в журнале сделок. Журнал — единственный источник для статистики, налогов, аудита и отчётов ГМ.

```yaml
id: 184467
tick: 37
kind: wage                 # тип потока: строка матрицы потоков
legs:                      # ноги операции, каждая сбалансирована по инструменту
  - {op: redeem,   instr: DEP, issuer: bank_3, holder: firm_120,       amount: 4500000, ccy: RUB}
  - {op: transfer, instr: RES, issuer: cb_RUB, from: bank_3, to: bank_7, amount: 4500000, ccy: RUB}
  - {op: issue,    instr: DEP, issuer: bank_7, holder: hh_n_25_mid_d5, amount: 4500000, ccy: RUB}
declared: true             # видит ли сделку налоговая и статбюро
settlement: noncash        # cash | noncash | barter
legality: legal            # legal | illegal
region: north
```

Та же зарплата «в конверте»:

```yaml
kind: wage
legs:
  - {op: transfer, instr: CASH, issuer: cb_RUB, from: firm_120, to: hh_n_25_mid_d5, amount: 4500000, ccy: RUB}
declared: false
settlement: cash
legality: legal            # сама зарплата законна, незаконно её сокрытие
```

Правила для признаков:

1. `legality: illegal` ⇒ `declared: false` (нелегальные рынки, взятки, дань не декларируются).
2. Налоги начисляются только по задекларированным сделкам. Незадекларированная сделка может быть раскрыта проверкой
   с вероятностью, зависящей от бюджета налоговой службы, качества судов и способа расчёта: у наличных она ниже, чем у безнала.
   Раскрытие порождает доначисление налога `TAXA` и штраф.
3. Незадекларированный безнал возможен (фиктивные договоры, обнал), но его риск раскрытия выше. Параметр `detect_noncash_mult`.
4. Бартер не создаёт финансовых ног и не платит налогов, если не задекларирован.

## 8. Истинная и официальная экономика

- **Истинные счета** строятся по всему журналу. Их видят ядро (для проверок) и ГМ.
- **Официальные счета** строит статбюро: только задекларированные сделки, плюс оценка теневой части по собственной модели статбюро
  с ошибкой, плюс задержка публикации и последующие пересмотры.
- Статбюро **не читает истинные счета напрямую**. Иначе игроки получали бы идеальную информацию.
- Правительство может публиковать искажённые цифры (`published_bias`). Агенты, особенно иностранные инвесторы,
  постепенно сравнивают официальные цифры с косвенными признаками (налоговые сборы, импорт, потребление электроэнергии),
  и при раскрытии расхождения падает доверие и растёт премия за риск.

Методика статистики описана в разделе 06.

## 9. Денежные единицы и точность

- Суммы денег хранятся целыми числами в минимальных единицах валюты (`i128`). Числа с плавающей точкой используются только в
  поведенческих расчётах (сколько потратить, какую цену поставить); перед проводкой результат округляется до минимальной единицы.
- Округление — к ближайшему, остаток от разделения сумм (например, процентов по когорте) переносится явно, чтобы сумма сходилась точно.
- `i128` выбран из-за гиперинфляции: при росте цен в миллиарды раз `i64` переполняется. Государство может провести **деноминацию** —
  событие, которое делит все суммы в валюте на 10ⁿ во всех балансах одновременно.
- Годовые ставки переводятся в ставку за тик: `(1 + r)^(1/12) − 1`.

## 10. Проверки после каждого тика

Нарушение любой проверки — ошибка в коде. В режиме разработки симуляция останавливается и сохраняет снимок мира.

1. **Нулевая сумма инструментов.** По каждому финансовому инструменту в каждой валюте сумма активов минус обязательства всех агентов мира равна нулю точно.
2. **Сбалансированность сделок.** У каждой записи журнала ноги сбалансированы по каждому инструменту.
3. **Уравнение чистой стоимости** (п. 5) выполняется для каждого агента точно.
4. **Неотрицательность.** Наличные, резервы, депозиты и счёт казначейства у держателей не меньше нуля. Овердрафт оформляется как `LOAN` или `CBL`.
5. **Сохранение товаров.** По каждому товару и региону: запас на начало + выпуск + импорт = промежуточное потребление + конечное потребление + инвестиции + экспорт + запас на конец + потери.
6. **Труд.** Отработанные часы каждой когорты не превышают доступных.
7. **Платёжный баланс по истинным счетам** сходится без статистического расхождения: текущий счёт + счёт капитала + финансовый счёт = 0
   (финансовый счёт со знаком «чистый приток капитала — плюс»).
8. **Матрица потоков.** Для каждой страны суммы всех строк и столбцов матрицы потоков за тик равны нулю.

## 11. Принятые решения

Решения согласованы с Романом в ревью PR #1 (25 октября 2026).

| Вопрос | Решение |
| --- | --- |
| Учёт акций | обязательство эмитента по рыночной стоимости, как в СНС |
| Деньги бюджета | на счёте казначейства в ЦБ (`TSA`); хранение в коммерческих банках — настройка эпохи |
| Получатели взяток | отдельная когорта домохозяйств «чиновники» с распределением по регионам и ведомствам |
| Балансы регионов | не ведутся отдельно, выводятся из признака `region` у агентов и сделок |
